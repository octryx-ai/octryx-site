OCTRYX AI · THE PLATFORM

Your team, your agents, your systems.

Octryx AI is the layer above your coding agents. Your developers keep working locally with the agent they know. The platform orchestrates, checks, records and opens pull requests, and connects to the systems you already run. Every part below carries its real stage.

Where the work happens

All coding work is done by a coding agent on a person’s own machine. The server never writes your code; it keeps the process around it.

In real runs

On the developer’s machine

Claude Code does the work: code, tests, stories. Codex support is experimental. A plain claude stays unchanged, and nothing is written to ~/.claude.

The machine checks every job against its own allowed folders, macOS permissions and a local deny list. Credentials, uploads, git push and deletes outside the repository are refused locally.

In real runs

On the server

Octryx AI orchestrates the workflow, runs the pipeline, has an independent reviewer check the result, keeps the record and opens the pull request. People merge.

The chat assistant runs on the server with your company models through the gateway.

In real runs

Developers keep working locally

You do not have to give up your terminal or your editor. Octryx AI works above the agent you already use, and you can still use it alone.

Own subscription or company model

A session uses the person’s own Claude or ChatGPT subscription if the Workspace allows it, otherwise a company model through the Octryx AI gateway, logged and counted. The remaining 5-hour and 7-day allowance is shown.

When the subscription runs out

When a person’s subscription allowance is used up, the run falls back to a company model of the same class and returns to the subscription after the reset. The work can also be handed to a colleague with spare allowance; by default a person confirms the takeover, and a Workspace can make the offer automatic (Built).

A second pair of eyes on every pull request.

Octryx AI reviews pull requests on GitHub, GitLab and Bitbucket, including the ones its own runs open. It informs, it does not block: the team decides. It learns from corrections, so a finding a team ignores with a reason can become a rule.

HOW IT WORKS
  1. 01A pull request opensThe platform’s own pull requests are picked up within about 5 seconds; others by webhook or by the hourly sync.~5 s
  2. 02Independent reviewA separate model reviews the diff, the ticket, the specification and the tests the server confirmed.~24 s
  3. 03Summary and inline findingsOne summary comment, findings on the exact line, each with a severity. A suggested change covers exactly the lines it replaces. An objection a person made in the thread is not repeated.
  4. 04A status that informsBy default the status stays green and counts the findings. A team can switch a repository to a gate.
  5. 05Answers in the threadCommands in a comment; only people with write access can use them.
  6. 06After a fix pushAn incremental pass: the finding is marked fixed, its thread resolved, the summary edited in place.
Times from live tests: about 2 seconds to pick up the platform’s own pull request, the first comment after about 24 seconds; in the measured demo run 23 seconds.
COMMANDS IN A COMMENT
@octryx review fullA full review of the current head, not an incremental pass.
@octryx pause / resumeNo review starts for this pull request until it is resumed.
@octryx explain [question]In a finding’s thread: why it matters and how to fix it.
@octryx ignore [reason]Closes the finding and proposes a team rule from the reason, for a second person to approve.
@octryx fix [note]A fix run pushes a reviewed fix. Off unless the repository allows fix runs.
@octryx write testsA fix run that adds the missing tests. Off unless allowed.
SETTINGS PER REPOSITORY
  • Off until an admin switches it onPer repository: webhook, hourly sync, both, or off.
  • Status policyinform (default): green, findings counted. gate: red on blocking findings, as a required check.
  • Size brakeReads carefully up to 800 lines or 25 files; larger pull requests get a note instead of a shallow review.
  • Drafts and fix runsDraft pull requests and fix runs are off by default. The bot never merges.
Honest limits A failed status for a committed secret comes with the secret scan, which is still being built. Suggested changes are checked before posting only for Python so far (including unknown names); for other languages they are posted unchecked.
