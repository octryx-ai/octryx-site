Now

v0.0.1-alpha
16 items · open one to read more
Two coding enginesClaude Code: In real runsCodex: Built

Claude Code runs on your developers’ machines through the platform; Codex support is experimental. Each workspace sets its default engine. Codex is tried on a local installation; no run with Codex has gone through to a pull request yet.

Your own subscription or a company modelClaude seat: In real runsCodex seat: Built

A session uses the person’s own subscription if the workspace allows it, otherwise a company model through the Octryx AI gateway, logged and counted.

Independent reviewIn real runs

A reviewer in its own session, with no access to the author’s session, checks only what the server read itself: the diff, confirmed tests and screenshots. Hard limits pause a run instead of letting it continue silently.

Guard rails per phase and runBuilt

Each phase may only use the model it is set to; a request for another model lands on the allowed one. A cost budget per run pauses the run when it is used up. A pull request is opened only for the exact state the pipeline tested green. Each engine gets its own reviewer session.

Prompt-injection fencesBuilt

Content from knowledge and from connectors reaches a model marked as untrusted data, never as instructions.

ConnectorsJira, Confluence, Bitbucket, GitHub PRs: In real runsServiceNow, Kubernetes, custom REST: Built

Jira, Confluence, GitHub, Bitbucket, ServiceNow and Kubernetes. Admins can add any REST API without code, including OData, and grant it per workspace. Every write needs a confirmation.

Approvals on desktop and phoneIn real runs

Tool approvals and standing approvals per workspace, decided in the browser or in the phone web app. Approvals say in plain words what they are for.

Knowledge with sources and citationsIn real runs

Every answer links to the passage and the original source. Hybrid search and a knowledge graph per workspace.

Memory that people confirmBuilt

Agents propose what to remember. It stays unconfirmed until a person confirms it, and forgetting really deletes. Off by default.

Local models with permissive licencesBuilt

By default only permissively licensed local models are offered. Others need an explicit choice that shows the licence note.

Pull request review botGitHub, GitLab: In real runsBitbucket: BuiltSecret scan: Building

Octryx AI reviews pull requests, including the ones its own runs open. It picks them up within about 5 seconds (2 seconds in a live test); the first review comment came after about 24 seconds. GitHub and Bitbucket. On GitLab it has been tried in real runs on a self-hosted instance: a summary with inline findings, the commands explain, pause, resume and ignore, and an incremental pass after a fix push that marks the finding fixed and closes its thread. On GitLab it reacts through a webhook or by polling, both tried live. The review status informs by default: findings are counted and the status stays green. A team can switch a repository to a gate. A failed status for a committed secret comes with the secret scan.

Secrets stay outBuilt

Secret redaction covers prefixed names, JSON and YAML, quoted values, URLs and known token forms. Output from a developer machine is redacted before it leaves the machine.

Nothing installed system-wideBuilt

The launcher brings its own pinned tools: ast-grep, Playwright, Chromium and gitleaks.

From correction to checkBuiltAutomatic checks: Building

When a person corrects an agent, the correction is captured and counted. A check proposed from it needs a second person to approve it. Proposing and proving checks automatically comes next.

Fair browser testsBuilt

A browser scenario that cannot work on an app is detected and never counted as a failure of the agent.

Marking of AI-generated workBuilt

Commits, pull requests, Jira and Confluence get a marker naming the model. This helps with the marking duty of the EU AI Act, Art. 50(2); it does not make anyone compliant on its own.

11 items · what we work on now
BuildingAn install package for any Kubernetes

The repository is public under Apache 2.0, and a Helm chart with its guide is in the docs. Next: a package tested on more clusters than ours. No cloud lock-in.

BuildingA published benchmark: “Coffee”

One real web app, built by Octryx AI once with Claude Code and once with Codex. We publish the prompt, the spec, the cost, screenshots and the test report.

PlannedCodex runs on our preview installation

Codex support is built and experimental. Next: a complete run with Codex through to a pull request, then real workflows on the preview installation.

BuildingCloser to a coding agent on its own

Octryx AI adds tests, an independent review, a pull request, cost records and audit around the agent. Next: the same cases measured in tokens against Claude Code on its own. On Flutter, the build and the browser test take most of the time. The numbers and their limits are on the Benchmark page.

BuildingTake a session to another device

Continue a whole running session on another device. Today a session can go to a colleague, and a run falls back to a company model when a subscription runs out.

BuildingCodex on the server

Codex is an open-source coding agent under Apache 2.0. Once its integration is finished, Codex can run directly on the server, not only on a developer’s machine. It replaces the earlier coding runtime on the server, which we dropped.

PlannedColleagues first, then a company model

When a subscription reaches its limit, the run continues on a company model so nothing stalls, and the work is offered at once to the colleague who uses the least of their subscription. When someone accepts, the work moves to their subscription and the company model stops. An admin can decide that the offer is always accepted. Today the two happen separately.

PlannedConnector gallery

Find a connector by searching, with the vendor’s icon for recognition (freely licensed icons) and in groups: tickets and knowledge (Jira, Confluence, ServiceNow), code (GitHub, GitLab, Bitbucket), CI (Jenkins), runtime and cloud (Kubernetes, AWS, Azure, Google Cloud) and observability (Prometheus, Loki).

PlannedEvery connector proven

Each connector gets a real test against a real service: local containers for Jenkins, Prometheus, Loki and Kubernetes, emulators or test accounts for Azure and Google Cloud. Until then a connector is called Built.

PlannedUI and UX extension

A broader, more consistent interface across all pages of Octryx AI.

PlannedModels per workflow area

Choose which model works in which part of a workflow.
