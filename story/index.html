THE STORY · ABOUT 3 MINUTES

Not a better agent. A better system around agents.

AI makes individuals faster. I want it to make teams smarter. This is how Octryx AI came about, and what it is trying to be.

It started with the first coding agents

When the first coding CLIs came out, the potential was obvious. So was the fact that they weren't there yet. I did what many developers did: I tried to build my own agent from scratch.

It taught me something that should have been clear from the start. One person can't out-build teams with almost unlimited resources. The CLIs overtook my agent fast, and they keep getting better. That was fine. It meant I could stop competing with them.

Speed without lasting quality

But the problems I had seen along the way stayed. I build Octryx AI itself with coding agents, every day, and I kept seeing the same pattern:

  • Files and functions grow far too large.
  • Old code stays behind and piles up.
  • A test gets fitted to one scenario instead of solving the problem in general.
  • Step by step you lose the overview, and with it the ability to understand your own code base.

Agents don't question themselves, so one wrong turn can cost days. You win that time back, because agents write code so much faster. But on a large code base, speed alone doesn't last. A controlled process is what matters most.

I watched other people work with agents, too. Some were afraid to use them; others handed over everything. Neither is the providers' fault. It's how we use them: alone. One person, one agent, and the rules in that person's head or in a markdown file on their machine.

The shift

So I stopped trying to build a better agent and started building the layer above them. The coding agent keeps doing what it is good at: writing code on a developer's machine. Octryx AI decides the steps, checks the result, keeps the knowledge and writes down what happened.

  • One process. Phases your team defines, from a work item to a reviewed pull request.
  • One set of rules. Code style and agent instructions in one place, versioned, given to every agent at the start of a run.
  • One record. Who asked, which agent, which model, which tests, what came out.

The idea: teams smarter, not just individuals faster

Collective knowledge. If one person works out how something is done well, the whole team should be able to reuse it one to one, and so should the agents. Today that means shared rules and a shared search with sources. Later, I hope, the knowledge of a whole company, not only its code.

Trust through evidence. You shouldn't have to believe an agent. A test that fails on the old code and passes on the new one, an independent review, a record you can check afterwards.

A better process over a bigger model. The newest models make a lot possible, but their cost is hard to control. I want to get the most out of small and local models, and a good process helps them more than a bigger model would. How to hand knowledge cleanly to a language model is also the subject of my bachelor's thesis. One example from the current development: the agent used to see 101 tools on every turn, about 19.8k tokens. Now it sees 10 core tools and searches for the rest when it needs them, about 2.1k tokens.

Open source. One person can't cover everything or try many solutions at once. A community can. Octryx AI is self-hosted and Apache 2.0.

Where it stands

Early. v0.0.1-alpha is public. It is for coding teams: Claude Code does the work, and Octryx AI takes a work item to a reviewed pull request. In our six test cases, all six got there with no human step. Codex support is experimental. There is no community yet; the repository has just gone public. In development on the 0.0.2 branch, not released yet: Codex as a second engine, on the developer's machine and on a server; runners on a server, a container pool with no personal credentials in the container; and one gateway for all model traffic through a bundled LiteLLM. The roadmap shows the real stage of every part.

If this matches problems you have seen, I'd like to hear from you. If it doesn't, even more so. Open an issue on GitHub or write to info@octryx.ai.
