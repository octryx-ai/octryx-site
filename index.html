Rules in one place, not in markdown files.

This is the main difference to a coding agent on its own.

A CODING AGENT ON ITS OWN
  • Rules live in markdown files in each repository (CLAUDE.md, AGENTS.md) or on one person’s machine.
  • Every repository keeps its own copy, and the copies drift apart.
  • Nobody sees who changed a rule, or which version an agent used.
WITH OCTRYX AI
  • Code style, team rules and agent instructions live in the platform: set once for the installation, a Workspace or a repository.
  • Versioned and audited; a change is visible, and a run records which version it used.
  • Every agent gets them at the start of a run, on any developer’s machine.

Where Claude Code alone is better today For one developer on one quick task it needs no setup, and in our own tests it produced the nicer UI. Use Octryx AI when a team needs a shared process, independent review and a record — not to go faster alone.

THE STORY

Not another agent. A team around the agents.

Octryx AI started with the first coding CLIs. The potential was obvious, and so was the fact that they weren't there yet. So I tried to build my own agent from scratch. I learned quickly what should have been clear: one person can't out-build whole teams with almost unlimited resources. The CLIs overtook my agent fast.

But the problems I had seen along the way stayed. Today's CLIs are excellent, yet once you really use their potential, you lose the overview. I saw it while building Octryx AI with agents myself. Files and functions grow far too large. Old code stays behind and piles up. A specific test scenario gets hard-coded instead of solved in a general way. Step by step you lose the ability to understand your own code base. And agents don't question themselves, so a wrong turn can cost days. You win that time back, because agents write code so much faster. But in a large code base, a controlled process is what matters most.

I watched people work with them. Some were afraid to; others handed over everything. That isn't the providers' fault. It's ours, because we use them alone.

That is what I set out to fix: not one person alone with an agent, but a team working together, with a shared process, shared rules and shared knowledge. It took many experiments and, honestly, a lot of burned tokens. How to hand knowledge cleanly to a language model is also the subject of my bachelor's thesis.

The newest models make a lot possible, but their cost is hard to control. So the question became: what if we get the most out of small and local models? If one person defines how something is done well, the whole team can reuse it one to one, and agents can take the work over.

The goal is simple: more time, output that is what it should be, and fewer beginner's mistakes. What one of us knows should be what the team knows.

— Luca Campisi, founder

RUN IT YOURSELF

Start on one machine. No cloud lock-in.

Octryx AI needs Postgres, S3-compatible object storage and a model endpoint — nothing vendor-specific. The coding agents run on your developers' machines; each run can get its own short-lived sandbox container.

One machine with DockerBuilt
Docker Compose brings up Octryx AI with Postgres, object storage and migrations on a single host. Enter your model access in .env; secrets are generated for you. git clone https://github.com/octryx-ai/octryx.git cd octryx cp .env.example .env # fill in one model block docker compose up -d --build # with the demo Workspace: docker compose -f docker-compose.yml -f docker-compose.demo.yml up -d --build
