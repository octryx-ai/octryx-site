Design guide for the web app ​

Design contract. This page is the single source of truth for every surface of the Octryx AI web app (frontend/chat in the repository). If this page and the code contradict each other, this page wins. Patches that violate it are not merged. Living document: every extension of the system lands here first, then in the token files, then in the code.

The values live only in the code: frontend/chat/src/styles/chat/ds-tokens.css (sizes), ui-set.css (shared component shapes) and theme-base.css (colours, light and dark).

0. Hierarchy of truth ​

This wiki page                      ← rules, principles
     ↓
ds-tokens.css · ui-set.css · theme-base.css   ← token implementation (+ domain CSS alongside)
     ↓
Live React code                     ← must not deviate from here

A deviation in the code that is not documented on this page counts as a visual bug.

1. Design principles ​

Five sentences. They stand above every detail rule.

#PrincipleMeaning
P 01Calm surfacesBorders + gentle elevation instead of shadows. Gradients may appear only as atmosphere, never as content color.
P 02Accent is meaningThe cream accent marks focus / route / in flow. Green is exclusively the semantic “Active”. Never swap them.
P 03Drawer instead of modalCreate / edit is always a right side drawer. Modal dialogs only for pure confirms.
P 04Table-first for listsData is tables, not walls of cards. Cards only for elements with icon + hierarchy + > 3 sub-values.
P 05Global ≠ projectCredentials and definitions are global. Assignment and usage are per project. UIs must make this separation visible.

2. Brand identity ​

2.1 Mark ​

  • File: assets/logo.png
  • Shape: round circle, 1:1
  • Minimum size: 24×24 px
  • Usage: only on a neutral or taupe background — never on a colored surface and never tinted.

2.2 Brand palette — the five values ​

2.3 Accent ≠ Status ​

The strict separation:

TokenValue (Dark)Value (Light)Role
--accent#E8DFC5#4F4840Visual accent — focus, active tabs, primary
--accent-strong#F3ECD6#2B261FHeadlines, accent text, inline code

Don't: use sage green where accent is meant (e.g. primary button fill, tab underline). If a surface looks too green to you — it is.

2.4 Tone of voice ​

  • Direct, technical, concise. No marketing phrases, no exclamations.
  • Imperative in action buttons: “Save changes”, “Delete forever”, “Publish” — never “Save my changes please”.
  • Sentence case in headers (except brand & proper names). Never Title Case Everywhere.
  • English throughout: the UI, the docs and the internal specs.

9. Components — Catalog ​

9.1 Buttons ​

Four variants × two sizes. No fifth variant. No third size (except the icon-only close at 2.3rem).

VariantClassUsage
Primary.admin-panel__action-btn--primaryThe one most important step. Max 1 per action row.
Default.admin-panel__action-btnSecondary, cancel, tertiary
Danger.admin-panel__danger-btnDestructive action. Always with confirm.
Ghost.admin-panel__action-btn + transparentTertiary, “View docs ↗”
SizeHeightPaddingFontUsage
Default1.9 rem0.35rem 0.7rem0.78remDrawer footer, section header, forms
Compact1.4 rem0.2rem 0.5rem0.7remTable actions only
Icon Close2.3 rem0 (square)—Drawer close X

Compact rule: Compact is a size variant, not a wording. Labels stay full (“Edit”, “Delete”). When space is short → icon-only variant. Forbidden: Del, Ed, Sv, Rmv, etc.

States:

  • Hover: brightness +8%
  • Focus: 3px accent ring (box-shadow: 0 0 0 3px var(--accent-soft)), never the native outline
  • Disabled: opacity: 0.45; cursor: not-allowed;
  • Loading: spinner + disabled, the label stays visible (e.g. “Saving…”)

Button group order: Cancel on the left, Primary/Danger on the right. Gap always 0.4rem.

9.2 Form fields ​

Uniform geometry for every input field:

  background: rgba(255,255,255,0.04);

  outline: none;
  transition: border-color 160ms, box-shadow 160ms;

.form-input:focus {
  border-color: color-mix(in srgb, var(--accent) 50%, transparent);
  box-shadow: 0 0 0 3px var(--accent-soft);
}

Variants: input[type=text|url|email|password|number], <select>, <textarea> — all share the geometry.

Validation states:

Search field — fixed pattern:

9.9 Tables ​

  • Header: sentence case (like DataTable), 0.74rem (--ds-font-size-small), weight 600, muted; no uppercase, no letter-spacing — one header font in all tables
  • Body: 0.82rem
  • Sortable columns: ↑↓ indicator
  • Row click → detail drawer
  • Actions: on the right, compact buttons with full labels
  • Empty: .admin-panel__empty-state (centered, 2 lines, no icon)

9.10 Overview / KPI Cards ​

  • Max 4 cards in a row
  • Label on top (eyebrow), value large (1.35rem 700), meta below (0.7rem muted)
  • Trend: ↑ green, ↓ red. Never a donut or bars here — KPIs are numbers.

10. Light/Dark — Validation Matrix ​

Every new component must pass in both themes. If even one of the following checks fails → the patch is blocked:

  1. Primary button is clearly recognizable in both themes (fill + border + text contrast).
  2. Default button border is visible in light (not white on white).
  3. Danger button text is dark red in light (#B91C1C), not light pink.
  4. Inputs have a visible border in light (at least rgba(36,39,35,.12)).
  5. Search field magnifier icon is dark enough to recognize in light.
  6. Badges text + border meet WCAG AA contrast in both themes.
  7. Inline code has dark accent text on light beige in light (not light on light).
  8. Inline success/error boxes have dark text with a strong border in light.

11. Architecture — Global vs Per-Project ​

Octryx AI is multi-tenant. The data models and UIs must make the separation visible.

11.1 Global · Infrastructure ​

What the platform provides. Set up once, applies to all projects. Sits under Platform in the admin sidebar.

  • LLM Provider Credentials (StoredSecret.project_id = NULL)
  • TTS / STT Provider Credentials
  • Agent & Mode Definitions (Catalog)
  • MCP Server Definitions
  • Runtime Execution Settings (Docker, PIDs, security)
  • Branding · OIDC · SSO

11.2 Per-Project · Usage ​

What a project uses of it. Isolated per project. Lives in the Project Settings Drawer.

  • LLM Provider Assignment (WorkspaceCapability)
  • TTS / STT Usage Config (project.config)
  • Channels (project_id FK)
  • Built-in Tool Configs (project_id FK)
  • Workspace Policy (routing, runtime)
  • Agent / Runtime / Workflow Bindings

11.3 Data schemas ​

jsonc
// project.config (per-project, JSON column)
{
  "tts": { "enabled": true, "provider": "openai", "default_voice": "nova", "default_speed": 1.0 },
  "stt": { "enabled": true, "provider": "openai" }
}

// StoredSecret (global, project_id = NULL)
{ "key": "openai_tts_api_key", "project_id": null, "value": "sk-…" }

11.4 UI rule ​

Global tabs sit under Platform in the admin sidebar. Per-project settings live in the Project Settings Drawer. Never mix them in the same view.

12. Do & Don't ​

✓ Do ​

  • Use CSS tokens (var(--accent), var(--border-soft)).
  • Section header with eyebrow + bottom border.
  • Lists as a table, detail in the right drawer.
  • Required: red asterisk, not the word.
  • Compact buttons with full labels (“Edit”, “Delete”).
  • Accent (cream) for focus / route / brand.
  • Green only for the “Active” status.
  • Inline success/error in the section.
  • Toast only for asynchronous feedback.
  • Sidebar collapsible, side panel via toggle (closed by default).
  • Check light + dark in the matrix (§10).
  • Separate global vs per-project visually.

✗ Don't ​

  • No hard-coded hex codes — everything via tokens.
  • No centered create/edit modals — always a drawer.
  • No shadows on cards (only drawer / modal).
  • No colored gradients as content color.
  • No two primary buttons in one action row.
  • No abbreviated button labels (“Del”, “Ed”, “Sv”).
  • No sage green as the visual accent (the brand is cream).
  • No cyan-tinted primary buttons (invisible in light).
  • Side panel not open by default — only via an explicit toggle.
  • No toast for static form validation.
  • No emoji as a UI icon.
  • No wall of cards instead of a table for > 5 entries.
  • Never tint the logo, place it on a colorful surface or shrink it below 24×24 px.

15. Versioning ​

This document follows SemVer on token/component breaking changes:

  • Major (v2.0): breaking change in tokens (e.g. renaming --accent).
  • Minor (v1.x): new component or new variant, backward compatible.
  • Patch (v1.0.x): token value correction, docs fix.

Current version: v1.0.0 — brand re-tokenization (sage green → cream/taupe), light-mode fixes, sidebar/panel toggle pattern documented.
