Good first issues ​

Small, self-contained changes to start with. Each is data or a few lines plus one test, and names the file, the change, the test and when it is done. Issues marked "not open yet" wait for a change that is still being merged.

Rules for every issue ​

  • Run the focused test first, then open a pull request against the integration branch.
  • Run the merge gate: scripts/full-regression.sh --mode pr --wait. See How a pull request goes in.
  • Keep files at about 300 lines, at most 500. See Code style.
  • Comments explain why, not what.
  • A dependency version you pin must be at least two weeks old.
  • Build secrets in tests from pieces (for example "npm_" + "a1B2" * 9), so the secret scan does not flag the test file.

UI and launcher ​

How to run the checks. For UI issues, run these in frontend/chat:

  • npm test: the unit tests.
  • npx tsc --noEmit -p .: type checking.
  • npx eslint src: linting.

For launcher issues, run python -m pytest in clients/octryx-claude with its own venv.
