REST API ​

Built The web app, the launcher and the review bot all talk to the same HTTP API under /api/v1. You can use it for scripts and integrations.

Not a stable contract yet

Octryx AI is 0.0.1-alpha. The API can change between versions without notice. This page lists only the routes we have checked in the code; there are many more, mostly for the web app.

Signing in ​

POST /api/v1/auth/login takes the form fields username and password and answers with access_token, token_type (bearer) and refresh_token. Send the token as Authorization: Bearer <access_token>. A failed login is rate-limited and recorded in the audit log. Where an installation allows only single sign-on, a password login is refused.

bash
curl -s -X POST https://<your Octryx AI host>/api/v1/auth/login \
  -d username=<user> -d password=<password>

Coding clients sign in over OAuth instead: see MCP servers.

Main routes ​

RouteWhat it does
GET /api/v1/healthIs the platform up? Answers without a sign-in.
GET /api/v1/observability/healthThe detailed component checks. Admins only.
GET /api/v1/workflow-runs/startableThe workflows a run can start, for a Workspace (project_id) or a work item (work_item_id). For a work item it also names the workflow the next run would start with; nothing starts by itself.
POST /api/v1/workflow-runsStart a run: the workflow, the Workspace, optionally a work item, repository, branch and where it runs. It is refused for a Workspace or work item you may not start runs in.
GET /api/v1/workflow-runsList runs, filtered by status, work item or Workspace.
GET /api/v1/workflow-runs/{run_id}One run, with /events for its timeline.
GET /api/v1/flowsThe published workflows (include_inactive=true also lists those that are off).
POST /api/v1/flows/{flow_id}/activeSwitch a workflow on or off with {"active": true} or false. Platform admins only.
/api/v1/workspaces/{workspace_id}/check-proposalsThe checks proposed from corrections. Members read; approving, changing and rejecting need more rights. See Learning from corrections.
GET /metricsPrometheus metrics. See Metrics.

The MCP server for coding clients has its own endpoint, /api/v1/mcp/knowledge-protocol/mcp. See MCP servers.

Rules that apply to every call ​

  • Every call is checked against the caller's rights in the Workspace, the same as in the web app.
  • Sign-ins and refused requests are audited. See Governance.
