Jira ​

In real runs Jira Cloud, Server and Data Center. Octryx AI reads tickets as work items and as knowledge; agents can read and, if allowed, write.

Set it up ​

Admin › Connections › Add connection, type Jira:

FieldValue
Jira URLCloud: the site root, https://your-site.atlassian.net (no /jira). Server and Data Center: the base URL.
Authenticationone of the sign-ins below
Projectsthe project keys it may touch, for example OCX, SHOP

Sign-ins:

  • Cloud: email and API token: the account email and an API token from id.atlassian.com.
  • User and password: Server and Data Center.
  • Personal access token: Server and Data Center.
  • OpenID Connect client credentials: token endpoint, client id and client secret, optionally scope, audience and client authentication.

Test calls Jira's "myself" endpoint and answers "Connected to Jira (REST API 3)" or names what is wrong.

What Octryx AI does with it ​

  • Tickets: a JQL filter decides which tickets come in as work items, read on a schedule; a status mapping links Jira's statuses to Octryx AI's. Writing back status changes is part of the Workspace's work item workflow, not of the connection.
  • Knowledge: each issue becomes a document titled with its key, so agents cite it. Issues with a security level are always withheld. See Build your knowledge.
  • Agent tools, read: search tickets, read a ticket, users, projects, issue types, priorities, transitions, versions, boards and sprints.
  • Agent tools, write (only with Read and write, and with the confirmation described in Connections): transition, comment, create and update tickets, create and release versions, create sprints and add issues to them.
  • Workflows comment on the ticket, create a bug ticket and move it along, as the workflow defines.
  • Through Octryx AI's own MCP server, Jira is read-only.

Cloud and Server differ in their APIs (search, user ids, text format); Octryx AI handles both and remembers the API version per instance.
