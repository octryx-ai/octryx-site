Git repositories and pull requests ​

Built Octryx AI works in your Git repositories through a connection: runs clone the repository, push a branch and open a pull request, and the review bot comments on pull requests. Octryx AI never merges.

Supported hosts ​

How to connect each host: GitHub, GitLab, Bitbucket.

Add a repository for runs ​

A platform admin, or a Workspace admin for their own Workspaces, sets up the connection to the Git host once (Connections). Then, in the Workspace, open Work › Repositories › Add a repository for runs (Workspace admins and owners) and give:

  • the connection: the Workspace's GitHub, GitLab or Bitbucket connection;
  • the repository as owner/name and its base branch;
  • the rights a run has: read, branch, write and pull request are on by default, and each can be switched off;
  • optionally the test command, which the platform runs without the agent.

Octryx AI reads through the connection whether the repository exists. On GitHub it also finds the apps the repository declares; on GitLab and Bitbucket they are found when the first run prepares the repository. There is no server checkout: each run works in a clone on the machine it runs on.

Workspace settings › Data › Repositories shows the same repositories with their settings: source, branches, coding setup and the PR review bot. Editing a repository's setup in Work › Repositories leads there.

What a run does in Git ​

  • It works in a clone of the repository, on its own branch.
  • It pushes that branch and opens a pull request against the base branch.
  • On protected branches Octryx AI only ever opens pull requests; it never pushes there.
  • The pull request links back to the run's record: phases, evidence, tokens and cost.

Pull request review bot ​

The review bot reads pull requests and posts a summary, inline findings and a commit status. It is off until a Workspace admin switches it on for a repository. It never approves and never merges.

  • Overview: what a review looks like and where it runs
  • Set it up: switch it on and add the webhook, per host
  • Settings per repository: inform or required check, drafts, size limits
  • Commands: @octryx explain, ignore, pause, resume, review full, fix

Secrets ​

A run's job output is redacted for secrets on your machine before it is sent, and the platform redacts again before it stores or shows anything. See Secret redaction.
