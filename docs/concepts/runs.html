Runs and their record ​

A run is one workflow working on one work item. It has a requester, a responsible person, the machine and route it runs on, and a record.

The record ​

Every run keeps, next to its pull request:

  • each phase with its start, end and outcome;
  • the evidence: the proof "red on the old code", the pipeline's results, the browser scenarios, the review's findings;
  • every decision and approval, with who decided and when;
  • every step that was skipped or kept by the size class, with the reason;
  • tokens and cost: real API cost and, for seats, the list-price equivalent, kept apart.

The run card under Work › Runs shows what the run proved and what it cost. Operations › Live shows active runs with their last sign of life. See Operations.

Run memory ​

Built

Octryx AI remembers per repository and app what earlier runs learned, so the next run does not stumble over the same thing:

KindFor exampleKept
test commandthe command that really runs the tests6
environment fixa missing setup step6
alternative after a refusalwhat worked instead of a refused command10
large outputwhich command needs its output shortened6
app fact"data does not survive a restart", or a setup step that already fails on the app's base6

Run memory is information, never a permission: it appears in the phase brief under "information, not a rule". It is on by default; a Workspace can switch it off.
