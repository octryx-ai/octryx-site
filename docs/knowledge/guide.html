Build your knowledge, step by step ​

Built Connect your team's sources, keep them in sync, and let people and agents answer with cited sources. The sources and the search page are built; agents searching knowledge is In real runs.

Agents work from what your team has already written down: pages, tickets, code, manuals. Octryx AI reads these sources per Workspace, keeps every version it read, and makes them searchable for people and agents. Every answer links the passage it comes from, so you can open the source and check it before you rely on it.

The example is the Workspace Demo Shop, an online shop team with the Confluence space SHOP, the Jira project OCX, the repository demo-shop/checkout and two PDFs.

1. Open Knowledge › Sources ​

Open the Knowledge area of your Workspace and choose Sources. The page lists each source with its kind, what it reads, how many items it holds, its last sync and its state: Up to date, Synced, Syncing, Out of date, Needs attention, Paused or Never synced. Adding the first source turns Knowledge on for the Workspace. Only platform admins and the Workspace's admins and owners see this page.

2. Connect Confluence ​

A platform admin, or a Workspace admin for their own Workspaces, sets up the connection once under Admin › Connections, with the Confluence URL, the sign-in and the Workspaces it is Available in.

Then, under Knowledge › Sources › Add source, pick Confluence and name whole spaces by key (here SHOP) or page trees. Pages are synced; attachments and comments are not. Choose a schedule: manual, every 15 minutes, hourly, every 4 hours, daily at 06:00, or a custom schedule (at most every 15 minutes).

Restricted pages are withheld by default. Built A platform admin can turn on Enforce source permissions in this Workspace on the Sources page. The change needs a reason and is recorded in the audit log. From the next sync on, restricted pages are indexed and found only by the people Confluence lets read them.

3. Connect Jira ​

Add a source of kind Jira with one or more project keys (here OCX). An optional JQL filter can only narrow the project scope, never widen it. Each issue becomes a document with its key in the title, for example "OCX-14: Raise the free-shipping threshold to 60.00", so agents can cite the ticket.

Issues with a Jira security level are always withheld, even when the Workspace enforces source permissions. Separately from Knowledge, Jira and ServiceNow are polled every 5 minutes for changes that can start a workflow.

4. Add a code repository ​

Code comes in two ways:

  • A Git repository source reads a public repository on github.com, or a Bitbucket repository (Cloud, Server or Data Center) through its connection, at a branch or tag. Private GitHub and GitLab repositories are not read directly yet; use the local snapshot below.
  • A developer who starts octryx-claude in a checkout uploads the files at HEAD as a local snapshot, if the Workspace allows local snapshots. This is off by default; a Workspace admin or owner turns it on.

Text files are indexed with line ranges and secrets are redacted, so an agent can answer "Where is the free-shipping threshold configured?" with a link to config/shipping.yaml.

5. Upload PDFs and documents ​

Under Knowledge › Documents › Add document, upload PDF, Word, PowerPoint, Excel or HTML up to 32 MB, or text up to 8 MB. PDF, Office and HTML files are parsed in the background, in an isolated parser without network access.

Passages keep their page and section: a citation reads like "p. 4, § 3 Shipping rules". If you upload again with the same source key, Octryx AI adds a new revision, and you can compare revisions under Diff.

Parsing PDF, Office and HTML files needs the parser service installed with the instance.

6. Add research websites ​

Knowledge › Research websites sets which sites agents may use when they research the web for this Workspace. You approve or block each site, and choose the search mode: Open (blocked websites excluded) or Approved websites only. Research always reads only approved sites. Websites are not synced like Confluence. Web pages only become knowledge through a Package, after an author approves them.

Web search needs a search provider set up by a platform administrator. Without one, the page says that no search provider is configured.

7. Watch the sync ​

Open a source to see its Overview, Setup, Runs and Freshness. A run says how many items it listed, created, updated, left unchanged, retired, skipped or failed, and lists the items it handled. Sync now syncs the source right away. A page that was deleted at the source is marked Removed at source and is no longer found.

Scheduled syncs need the instance's sync scheduler switched on. Without it, only Sync now syncs.

8. Search ​

Open Knowledge › Search and ask a question in any language. Results are passages grouped by where they come from (documents, code, Jira, Confluence), with filters for source, space or project, and time. Above the passages, Octryx AI writes a short answer whose sentences link the passages by number. Ask in chat carries the question and the sources into a new chat.

Relevance ranking is optional. Without a reranker, the page says Relevance ranking unavailable and ranks by keywords and meaning only.

9. Explore the graph ​

Knowledge › Explore answers "what is connected to what". The List view shows relationships with the statement they were read from. The Graph view (admins) draws entities by type with a legend that is also a type filter, plus zoom, fit and a count line.

Admins build the rule-based manual, configuration and operations layers under Knowledge › Advanced › Structured graph. If a Workspace holds only documents and chapters so far, the graph shows those with a note saying so.

10. Use it in chat and in workflows ​

Ask in chat. The agent searches the Workspace's knowledge, answers, and links each statement to its source.

Under the answer, the Sources · 4 button (the number is the count of cited sources) opens Sources & evidence, the list of the cited sources.

The same search serves research steps in workflows, sub-agents and coding agents connected over MCP. If an answer cites none of the sources the agent found, the agent is reminded once to cite them; statements still without a source are marked in the answer.

11. Advanced (optional) ​

All built, admins only, under Knowledge › Advanced:

  • Packages: an agent researches a topic on trusted sites, and you approve what gets ingested.
  • Bindings: which other Workspaces this Workspace reads, and who reads this one; search reads across, nothing is copied.
  • Changes: what changed between two versions of a product, as cited facts.
  • Memory: what agents remember for the Workspace, and who may see it.
  • Episodes: whether sessions may return what they learned as episodes.
  • Engineering knowledge: versioned engineering packs the coding agent applies to changes.
  • Structured graph: the rule-based layers of the knowledge graph.
