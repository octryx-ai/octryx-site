Status on the pull request ​

The bot sets a commit status: octryx/review on GitHub, octryx-review on GitLab and Bitbucket. The names differ on purpose: GitHub uses the usual context/name form, while Bitbucket carries the key in a URL path where / is not possible, and GitLab follows Bitbucket. It shows pending while the review runs, then passes or fails.

  • Inform (recommended): the status passes and counts every finding, lows included, for example "Informational: 2 finding(s) to look at: 1 high · 1 medium · 1 low", or "No blocking findings · 1 low". Nobody is blocked.
  • Required check: the status fails when the review finds a blocking problem, which means a high or medium finding, or when the verdict is "changes requested". It blocks a merge only where the repository's branch protection (or GitLab's "Pipelines must succeed") requires the status.

A failed CI check, or a caller outside the diff that the change breaks, is added as a high finding. Under Required check that fails the status; under Inform it is reported and the status stays green.

When someone ignores the last blocking finding with @octryx ignore, a failed status turns green: "No blocking findings (1 ignored)".

A committed secret always fails the status, under Inform too: "1 committed secret(s): remove and rotate". The summary lists it as blocking, and the secret's value is never quoted. See Scanners.

Review drafts ​

Off: a draft pull request is reviewed once it is marked ready for review. On: drafts are reviewed too.

Protected branches ​

Branch names a fix run never pushes to, besides the target branch.

Fix runs ​

On: @octryx fix and @octryx write tests in a pull request comment may push onto that pull request's branch, never a protected branch, never forced. Off: the bot only reviews. A fix run also needs the PR fix workflow, which a platform admin switches on in Agents › Workflows. See Commands.

Size brake ​

Above either limit, the review adds "Large pull request" with a suggested split into stacked pull requests. It never blocks and never changes the status.

Hotspot paths ​

Files matching these globs, for example src/auth/**, are read with extra care, besides the built-in sensitive areas. They are listed under Look closely here in the summary.

Review on my seat ​

When on, the bot may offer this Workspace's pull request reviews to your device and your own Claude subscription. The first free seat takes a review; without one it runs on the company route. It is your choice only: on by default for admins and owners, off for everyone else. See Where the review runs.

Through the API ​

Every setting can also be set with PUT /api/v1/workspaces/{workspace}/repositories/{repository}/pr-review-bot (trigger, status_policy, review_drafts, protected_branches, fix_runs, size_limit_lines, size_limit_files, hotspot_paths). The call changes only the fields it sends. Every change is recorded in the audit log.
