Install with Docker Compose ​

Built One machine, to try and test Octryx AI. With the demo it is the First run; for development with hot reload, see Development setup.

You need ​

  • Docker Desktop, Rancher Desktop or Podman with docker compose 2.23 or newer (docker compose version). Give the container engine 8 GB RAM and 20 GB disk.
  • Internet access (base images, PyPI, npm, the model, the demo repository on GitHub).
  • Exactly one model access for the platform:
    • an Anthropic API key (simplest; https://console.anthropic.com). Octryx AI reaches it through Anthropic's OpenAI-compatible endpoint;
    • or any OpenAI-compatible endpoint with a key: OpenAI, Azure OpenAI, a LiteLLM gateway, vLLM, LM Studio or Ollama;
    • or AWS Bedrock with bedrock:InvokeModel in a region where the model is enabled;
    • or an OpenRouter key.
  • Coding runs on a developer's machine can also use the person's own Claude subscription through the launcher; that needs no platform key.
  • Chrome, Edge or Firefox.

Steps ​

  1. Get the code:

    bash
    git clone https://github.com/octryx-ai/octryx.git && cd octryx

  2. Configure one model:

    bash
    cp .env.example .env

    Open .env and fill in one block; leave the others commented out. LLM_PROVIDER takes anthropic, openai, bedrock or openrouter; any other provider is added later under Admin › Models › Providers. With an Anthropic key:

    bash
    LLM_PROVIDER=anthropic
AGENT_DEFAULT_MODEL=claude-sonnet-5
LLM_API_KEY=sk-ant-…

    For an OpenAI-compatible endpoint: LLM_PROVIDER=openai, LLM_ENDPOINT_URL, AGENT_DEFAULT_MODEL, LLM_API_KEY. For Bedrock: LLM_PROVIDER=bedrock, AGENT_DEFAULT_MODEL (a model id enabled in your region), AWS_REGION and the AWS keys. For OpenRouter: LLM_PROVIDER=openrouter and LLM_API_KEY. Any other value creates no model access; the start log then says startup.llm_provider_unsupported and names the valid values. With AWS SSO you can append the keys with aws configure export-credentials --profile <profile> --format env-no-export >> .env.

  3. Start. The first build takes 10–20 minutes:

    bash
    docker compose up -d --build

    • With demo content, add the demo file:

      bash
      docker compose -f docker-compose.yml -f docker-compose.demo.yml up -d --build

      (or COMPOSE_FILE=docker-compose.yml:docker-compose.demo.yml in .env). This creates the Workspace "Demo Shop":

      • a small sample shop in the repository demo/demo-shop on a local stand-in for GitHub at http://127.0.0.1:8434, on this machine only (clone it with git clone http://127.0.0.1:8434/demo/demo-shop.git);
      • its README and docs as Knowledge;
      • the connection "GitHub (demo)" and the PR review bot (status inform);
      • the work items OCX-1 (a bug) and OCX-2 (a story);
      • a Sample run in Work › Runs: a real Story / epic delivery run of OCX-2, recorded on another install, with its pull request and the bot's review on the local GitHub.

      No Jira, GitHub or other credential is needed beyond the model access in .env. The demo is ready when docker compose -f docker-compose.yml -f docker-compose.demo.yml logs demo ends with "demo: ready in the Workspace 'Demo Shop'". The same two files with down -v remove it again, with all volumes. docker-compose.yml on its own starts no demo and opens no demo port.

    • With Podman instead of Docker, first run export DOCKER_HOST=unix://$(podman machine inspect --format '{{.ConnectionInfo.PodmanSocket.Path}}').

  4. Sign in for the first time. There is no default password: a one-time setup code creates the admin.

    Get the one-time setup code:

    bash
    docker compose logs api | grep "setup code"

    The line names the setup page, http://localhost:8000/chat/setup (or your OCTRYX_PORT).

  5. Open that page. Enter the setup code, your name, e-mail and a password of at least 12 characters. From then on, you sign in with the username admin. The Setup guide opens and shows what is still missing.

Is it running? ​

  • docker compose ps: api is healthy; migrate and secrets-init exited with 0.
  • curl http://localhost:8000/api/v1/health returns {"status":"ok"}.
  • In the chat, ask "Reply only with pong". The answer is "pong".
  • Demo only: choose the Workspace with the top icon in the left bar (above "Chat"), then "Demo Shop". Knowledge › Search for "rollback" finds the incident runbook.

Common problems ​

Message or signCause and fix
required variable LLM_PROVIDER is missing.env is missing or no block is filled in (step 2).
port is already allocatedPort 8000 is taken. Set OCTRYX_PORT=8080 in .env and open http://localhost:8080/chat/setup.
No "setup code" in the logThe api is still starting. Watch docker compose logs -f api.
Search says "Choose a workspace"Click the Workspace icon at the top of the left bar and choose a Workspace.
Sign-in returns to the login page without an errorThe browser drops the Secure cookies on plain http. Use Chrome, Edge or Firefox and localhost, not the IP address.
Chat: authentication_error or invalid api keyThe endpoint's key is wrong or revoked. Fix it under Admin › Models (see the last row).
Chat: UnrecognizedClient, ExpiredToken, AccessDenied (Bedrock)The AWS keys are wrong or expired (SSO exports often last only hours). Export them again, then docker compose up -d.
Chat: model not foundThe model is not available to your key or in your region. Change AGENT_DEFAULT_MODEL (or AWS_REGION).
Setup guide: "has no price – costs are not counted"There is no list price for this model. This is only a notice. Enter the price under Admin › Models › Catalog (column Price / 1M (in · out)) and costs are counted too.
Model access changed after the first start, without effect.env is read on the first start only. After that, change the access under Admin › Models.

Start over: docker compose down -v. This deletes everything: database, documents and the generated keys.

For development with hot reload, see Development setup.
