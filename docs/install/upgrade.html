Upgrade, backup and uninstall ​

Built What to keep safe, and how to move to a new version.

Early software

Octryx AI is 0.0.1-alpha. Migrations are not automatically reversible. Back up before every upgrade. What we have checked so far is listed under What has been checked.

Upgrade ​

The database is migrated on every start: secrets-init creates missing keys (Compose only), then a one-time migrate step (a container in Compose, an init container in Helm) brings the database up to date, then the api starts.

  • Docker Compose: get the new version of the repository, then docker compose up -d --build.
  • Kubernetes: helm upgrade with the same values file.

Afterwards Admin › Platform › Version shows the installed parts. A healthy start has migrate and secrets-init exited with 0.

What has been checked ​

As of 21.11.2026:

  • An upgrade with a database migration on real data. One of our stacks with real data, including 136 runs, was started on a newer version. Its migrate step brought the database to the new revision before the api started. Afterwards every run, project and stored credential was still there and usable.
  • An upgrade on a fresh stack with demo data, from one alpha build to the next: backup, the new version started, the database at the new revision, sign-in working and stored credentials decrypting with the same key.

Not checked yet:

  • an upgrade with Knowledge data in the object store;
  • a restore onto a different machine, and a restore on Kubernetes;
  • an upgrade from a build before 21.11.2026, when the settings were renamed to OCTRYX_*. No public installation predates that.

Back up and restore ​

A backup has four parts, and it is only complete with all of them:

  • the database;
  • the keys that the first start generated: the signing key, the encryption key and the database password;
  • the files: app_data, app_uploads and the object store with the Knowledge documents;
  • .env.

Without the keys, every secret stored in Octryx AI (connection tokens, API keys) can no longer be decrypted, and every sign-in token becomes invalid. Keep the backup folder private: it holds those keys.

Docker Compose ​

Run the backup in the install folder. The volumes carry the project name as a prefix: octryx, or your COMPOSE_PROJECT_NAME. If you started the optional workers profile, stop those services as well.

bash
B=backup-$(date +%Y%m%d-%H%M); mkdir "$B"; B=$(cd "$B" && pwd)
docker compose stop api
docker compose exec -T postgres pg_dump -U oeuser -d octryx -Fc > "$B/database.dump"
docker compose stop object-store
for v in secrets app_data app_uploads object_store_data; do
  docker run --rm --user 0 --entrypoint tar -v "octryx_$v:/from:ro" -v "$B:/to" pgvector/pgvector:pg16 \
    -czf "/to/$v.tar.gz" -C /from .
done
cp .env "$B/env"; chmod -R go-rwx "$B"
docker compose start object-store api

Restore into a fresh install folder of the same version (the same git checkout or image), before its first start:

bash
B=/path/to/backup-…
cp "$B/env" .env
docker compose create
for v in secrets app_data app_uploads object_store_data; do
  docker run --rm --user 0 --entrypoint tar -v "octryx_$v:/to" -v "$B:/from:ro" pgvector/pgvector:pg16 \
    -xzf "/from/$v.tar.gz" -C /to
done
docker compose up -d postgres
until docker compose exec -T postgres pg_isready -U oeuser -d octryx; do sleep 2; done
docker compose exec -T postgres pg_restore -U oeuser -d octryx --no-owner --exit-on-error < "$B/database.dump"
docker compose up -d

The first start of the restored install keeps the restored keys, because the key generation only writes files that are missing.

For the demo, use -f docker-compose.yml -f docker-compose.demo.yml on every docker compose command, and add demo_git_remotes to both volume lists: it holds the local GitHub's repository and pull requests.

What has been checked (21.11.2026, the demo on a throwaway install): backup, down, restore into a new project. Afterwards the same sign-in token was accepted, the keys were identical, the stored credentials decrypted, the Knowledge search for "rollback" found the incident runbook, and the sample run and its pull request with the bot's review were there. Not checked: signing in with the administrator's password after a restore.

Rehearse a restore before you rely on it.

One Workspace ​

Settings › Organization › Backup & restore backs up one Workspace: its configuration, tasks, agents and skills. It is not a full backup: sessions, messages, runs, tool calls, traces, audit logs and secrets are not included. A restore never overwrites an existing skill unless you ask it to, and the page keeps a history of backups and restores.

Uninstall ​

  • Docker Compose: docker compose down -v deletes everything: database, documents and the generated keys.
  • Kubernetes: helm uninstall, then delete the volumes and the Secret yourself.
  • The launcher: curl -fsSL 'https://<your Octryx AI host>/octryx-claude/install.sh' | bash -s -- uninstall; --purge also revokes the login. See Launcher and devices.
